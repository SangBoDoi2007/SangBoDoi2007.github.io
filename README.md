# Cryo — official website (`sangbodoi2007.github.io`)

Landing page, privacy policy and `app-ads.txt` for **Cryo: Game Mode & FPS Meter** (`com.astvn.cryo`) by ASTVN Studios.

## What is in this repo

| Path | What it is |
| --- | --- |
| `index.html` | The landing page, Vietnamese and English side by side (`lang` on `<html>` picks which one shows). |
| `assets/site.css`, `assets/site.js` | Styles and behaviour of the landing page. No build step, no framework, no script from a CDN. |
| `assets/fx.js` | The expressive layer: inverted cursor, variable-font type, 3D shapes, scroll ticker, wavy progress. Pure decoration — the page reads fine without it. |
| `assets/polar.js`, `assets/numerals.js` | Polar Run drawn live on canvas; outline data for the big chapter numbers (generated by `tools/numglyph.py`). |
| `assets/lenis.min.js` | Lenis 1.1.13 (MIT), vendored from npm and loaded only on devices with a mouse. Update by hand. |
| `assets/perf.js` | Hidden frame-rate panel, loaded only when the address has `?perf` or `#perf`. "Tự cuộn 20 s" records while the visitor scrolls as usual; "Tìm thủ phạm" auto-scrolls several times, turning off one effect per pass. Reports hitches with the section they hit and, through Long Animation Frames, the code behind frames over 50 ms. It counts `requestAnimationFrame`, so on Android screens of 120 Hz and up it reads ~60 Hz: Chrome runs the main thread at half rate there (`ThrottleMainFrameTo60Hz`, on by default) while scrolling stays at full rate. Visitors never load it. |
| `tools/bust.py` | Stamps `?v=<content hash>` on every reference to a file in `assets/` (pages and scripts), so a reload after a push gets the new files. Run before every commit that changes `assets/`. |
| `privacy.html`, `assets/cryo.css`, `assets/cryo.js` | Privacy policy page and its own styles. Linked from the Play Console, so its URL must keep working. |
| `app-ads.txt`, `.nojekyll` | Ad-seller declaration and the flag that makes GitHub Pages serve files as they are. Do not edit by hand. |

## How the landing page is built

- **Colors** are Cryo's own Material 3 dark scheme, generated with `@material/material-color-utilities` (`SchemeTonalSpot`) from the
  same seed that produced the app screenshots (`#34437A`). The color picker swaps in four more schemes made the same way, the way the
  app follows the phone's wallpaper.
- **Motion** uses the spring constants from the app's `ui/theme/Motion.kt` (spatial 0.6/420, quick 0.45/1400, effects 1.0/1600,
  sheet 0.72/300): a small spring solver in `site.js` for interactive parts, and the same springs sampled into CSS `linear()` easings
  for hover and press states.
- **App panels** on the page are the real Cryo screens rebuilt in HTML/CSS, not screenshots, so they can be dragged, toggled and
  re-themed. The game shown is Polar Run, a demo game made by ASTVN Studios for this purpose.
- **Type** is Google Sans Flex (with its roundness axis) and Material Symbols Rounded, both from Google Fonts.
- **M3 Expressive details**: page-level components use the official expressive springs (fast spatial 0.6/800, default 0.8/380,
  slow 0.8/200; effects 1.0/3800 · 1600 · 800). The resolution slider, the wavy RAM ring and Shizuku progress line, the connected
  button groups, the switch with its check icon and the shape-morphing loading indicator follow the M3 Expressive component specs.
- **Expressive layer (`fx.js`)**: on a mouse, the cursor is an inverted (`mix-blend-mode: difference`) dot that turns into the
  exact pill of transparent buttons and links; around colour-filled buttons and images (logo, the Google Play badge, which
  must not be recoloured) it becomes a ring that hugs the button's live shape; leaving a button it shrinks back without
  rotating; it becomes a lens only while it is over the letters of a heading (not the empty rest of the heading's row); headings bloom from
  thin/condensed to their weight and swell with the `wght`/`wdth` axes near the cursor (chapter titles and the smaller card
  titles swell too, without the bloom); the hero, the light "paper" section and
  the finale carry clay-like 3D M3 shapes drawn on canvas in the current color scheme. With reduced motion or on touch, the
  cursor and swelling are off and every word is visible.
- **Cost rules** (measured with Chrome traces against the previous version): nothing runs while the page is idle (Lenis only ticks
  while scrolling, the ticker drifts on a compositor animation, shapes morph at most ~30 times a second and only on screen);
  never read `scrollY` or layout inside a write pass (use `view.y` from `site.js`); variable-font axes are rounded to steps so
  font instances are reused; locked heading lines are layout roots (`contain: size layout`) with their measured width and height.
- **Load and GPU rules** (#303, measured on an emulated phone with 4× CPU throttling and GPU raster): only what is on screen is
  built at load — the five chapter demos, the chapter numbers and the heading letter-splitting are built when they come within
  ~1–1.5 screens, or in idle time after the opening animation; images drawn into canvases are decoded off the main thread
  (`ImageBitmap`, `decode()`). Slow ambient drifts (background glows, chapter glows, 3D shapes) run as `steps()` keyframes that
  sample the same ease-in-out curve (~10–20 updates a second, under a pixel each), so the GPU redraws only when something moved;
  the three background glows step on the same 100 ms beat. Blurs sit on a static child of the animated element so they are
  rasterized once. The background glows are 128 px canvases scaled up by the compositor, so changing their tone does not repaint
  three screen-sized layers. Settled spring transforms are removed so finished elements leave the compositor.
- **Motion: two paths** (#303). Chrome on Android runs the main thread at half the screen rate on 120 Hz-and-up screens
  (`ThrottleMainFrameTo60Hz`, on by default), while scrolling and compositor animations keep the full rate. So on touch
  screens `go()`/`put()` in `site.js` solve each spring in closed form and hand it to Web Animations as keyframes (sampled at
  120/s like drawing every frame at 120 Hz, at most ~0.3 px off the true curve right as a stiff spring starts; samples
  that sit within 0.05 px of the line between their neighbours are dropped): blocks, cards and app icons fly in at the
  screen's rate and keep moving when the main thread is busy. Interrupting reads position and velocity off the running
  curve. Devices with a mouse, and heading words everywhere, keep the per-frame rAF spring: the main thread already runs
  at the screen's rate there, and a heading word must move in step with the letters reshaping inside it (on the compositor
  it ran a frame apart and shook, user report on a 165 Hz monitor). Letter shapes, chapter numerals, the wave and the games
  are drawn by script and stay at the main-thread rate. `…/?mo=main` forces the rAF path everywhere, to compare the two on a
  real phone; the `?perf` panel header names the path in use.
- **Split headings** (#303). Each letter is its own span, so the browser kerns a pair only while both letters share one
  font — true at rest, false while a heading "blooms" (each letter on its own axis step). Kerning switching on and off
  pair by pair made the line tail jump back up to 7.6 px as a heading finished. Headings that bloom (`k.kern` in `fx.js`)
  measure their kerning once at rest, turn the browser's off (`.kt.nk`) and add it to each letter's `letter-spacing`
  (in em): the rest look is unchanged to the pixel and nothing toggles mid-animation. Lines are re-locked only when the
  window width, the language or the loaded fonts for that heading's letters change, and always measured at rest.
- **Idle work** (`idleEach` in `site.js`) runs only with at least 3 ms of real idle time, never while scrolling or moving
  the mouse; the page always animates something, so the old 4 s timeout used to force jobs between frames. Only the
  queue deferred past the opening (`must`) still runs one job per timeout. Heading letter cells are pinned in idle time
  when a heading comes into view or finishes blooming, not on the first mouse approach. The canvas game runs at the
  screen's rate on mouse devices (up to ~220 Hz) and at most ~60 per second on touch screens.
- **Cache stamps.** GitHub Pages serves every file with `max-age=600`, and Chrome's ordinary reload re-checks only the HTML,
  so for ten minutes after a push a reload can still run the previous `site.js`. Every reference to a file in `assets/` —
  `href`/`src` in `index.html` and `privacy.html`, and `'assets/…'` strings in the scripts (`perf.js`, Lenis, the Polar Run
  images) — therefore carries `?v=<first 8 hex of the file's SHA-1>`. **Run `python tools/bust.py` before every commit that
  changes a file in `assets/`** (`--check` only reports); scripts are stamped before the pages, since stamping `site.js`
  changes its own hash. The `?perf` panel header shows the stamp of the `site.js` that is running.

## Rules for the copy

The page is linked from the Play listing, so it follows the same rules as the store text: describe what Cryo does to the system, never
promise results (no "boost", "more FPS", "cooler", "smoother"), say which features need Shizuku, and show no FPS numbers in any image
or demo.
